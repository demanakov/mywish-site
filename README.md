# MyWish — лендинг

Вёрстка макета Figma `To8XYwi7daHOnQlk0nnNPG`, нода **`914:193`** (Frame 86, 1440 × 10633).
Стек: **Next.js 16 (App Router) · TypeScript · Tailwind CSS v4**.

## Запуск

```bash
npm ci
npm run dev
```

Подключение формы к amoCRM и выкладка на хостинг — [`docs/crm-and-deploy.md`](./docs/crm-and-deploy.md).

## Как устроена вёрстка

**Масштабирование.** Вся страница тянется за шириной окна: корневой `font-size`
задан как `clamp(11.378px, 1.1111vw, 19.2px)`, то есть `1rem = 16px` при ширине 1440.
Любая величина из макета пишется как `px/16` rem — для этого есть хелпер
[`src/lib/px.ts`](./src/lib/px.ts): `box(130, 189, 551, 646)` принимает координаты
ровно как в Figma. Tailwind настроен так, что числовые утилиты — это пиксели макета
(`--spacing: 0.0625rem`, поэтому `w-325` = 325px макета).

Диапазон масштаба: **1024px → 0.71×**, **1440px → 1×**, **от 1728px → 1.2× и дальше
не растём** (сцена центрируется, по краям фон страницы).

**Структура страницы.** Hero — отдельный полноэкранный блок (`100svh`) с фоновым видео.
Всё остальное лежит на одной сцене шириной 1440 по координатам макета: в Figma страница
собрана плоско, абсолютным позиционированием, а художественные подложки свободно
пересекают границы секций. Отсчёт координат сцены — от нижнего края hero (макет y − 956).

## Проверка

Сервер должен быть запущен на `:3000`.

```bash
node scripts/verify.mjs
```

```bash
node scripts/adaptive.mjs
```

`verify.mjs` сверяет координаты двадцати ключевых элементов с макетом (сейчас все 20
сходятся до пикселя), `adaptive.mjs` проходит по ширинам 1024 / 1280 / 1440 / 1600 /
1920 / 2560 и проверяет масштаб, отсутствие горизонтального скролла, ошибки консоли и 404.

## Видео hero

Исходники `hero1080.mp4`, `loop1080.mp4`, `loop1080-24.mp4` лежат в корне (216 МБ) и
в сборку не попадают. Для веба они перекодированы в `public/video/`: интро 4.1 МБ (mp4)
и 3.1 МБ (webm), луп 3.1 / 1.4 МБ, постер 145 КБ. Сценарий: интро играет один раз,
дальше бесконечный луп; при `prefers-reduced-motion` остаётся только постер.

Пересобрать после замены исходников:

```bash
ffmpeg -y -i hero1080.mp4 -an -vf scale=1920:-2 -c:v libx264 -crf 25 -preset medium -pix_fmt yuv420p -movflags +faststart public/video/hero-intro.mp4
```

**Телефон и планшет (ниже 1024).** Роликов первого экрана нет. До 767 — свой зацикленный
ролик `public/video/hero-mobile-loop.mp4` / `.webm` (12 с, 652×1410, исходник `loop720.mp4`) с постером — первым кадром
`public/figma/1-hero/hero-mobile-video-poster.webp`, поверх — неподвижный градиент под текст.
768…1023 — фото `hero-mobile.webp` (исходник `мобфон.png`). Заголовок и кнопки — у нижнего
края экрана.

Последний кадр исходника повторяет предпоследний, и при повторе один кадр стоял бы дважды —
заметная заминка. Поэтому в веб-версии оставлены кадры 0…287 из 289. Пересобрать (постер —
первый кадр, `hero-mobile-video-poster.webp`; при смене пропорций поправить `--hero-art-h`
в `mobile.css`):

```bash
ffmpeg -y -i loop720.mp4 -an -frames:v 288 -c:v libx264 -crf 23 -preset slow -profile:v high -pix_fmt yuv420p -movflags +faststart public/video/hero-mobile-loop.mp4
```

```bash
ffmpeg -y -i loop720.mp4 -an -frames:v 288 -c:v libvpx-vp9 -crf 34 -b:v 0 -row-mt 1 -pix_fmt yuv420p public/video/hero-mobile-loop.webm
``` Шапка —
`MobileHeader.tsx`: слева звонок, по центру логотип, справа меню (разделы, «Оставить
заявку», телефон, Telegram, MAX, адреса). Сценарий тот же, но без
занавеса и сразу: шапка через 80мс, печать через 250мс (`MOBILE_HEADER_AT`,
`MOBILE_REVEAL_AT` в `Hero.tsx`). Ролики первого экрана и перехода к залам на телефоне
не скачиваются: в разметке `preload="none"`, загрузку включает скрипт только на десктопе.

Пересобрать фото после замены:

```bash
ffmpeg -y -i мобфон.png -c:v libwebp -quality 80 -compression_level 6 public/figma/1-hero/hero-mobile.webp
```

## Сценарий первого экрана

Отсчёт идёт от момента, когда видео реально пошло, — затемнение прячет загрузку.

Раньше раскрытие левого блока было привязано к хлопку героя в ролике (7.03с
руки сходятся, 8.02с разводит обратно), и вся анимация укладывалась в это окно.
Сейчас момент перенесён на 4.08с по просьбе заказчика: опорного события в кадре
там нет, камера просто едет, — поэтому внутренние доли сценария оставлены
прежними, сдвинута только точка старта. Обе величины лежат в `Hero.tsx`
константами `HEADER_AT` и `REVEAL_AT`.

| Момент | Что происходит |
|---|---|
| 0 → 0.3с | чёрное полотно уходит, видео играет в чистом виде |
| 0.36с | верхняя панель выезжает сверху вниз с 56px: логотип, меню, Telegram, MAX, телефон — с шагом 90мс, 900мс на элемент |
| 4.08с | подложка выезжает слева направо (380мс), одновременно внизу проступает растворение кадра в цвет страницы (380мс) |
| +0 → 0.41с | заголовок печатается по букве (12мс/символ) с кареткой |
| +0.19с | акцентное слово «ПРАЗДНИКИ» коротко клюёт масштабом |
| +0.43 → 0.78с | подзаголовок печатается (6мс/символ) |
| +0.62 / 0.68с | кнопки всплывают пузырями (260мс, back-out) |

Сверить тайминги: `node scripts/hero-timing.mjs` — ловит оба момента от старта
видео в обоих режимах анимации.

Всё на CSS: анимации идут мимо основного потока и не спотыкаются, пока
догружается видео. Свойства только `transform`, `opacity` и `clip-path`.
Сценарий играет и при включённом `prefers-reduced-motion`: это часть продукта,
а не украшение. Общее правило доступности глушит длительности у всего подряд,
поэтому для сцены они возвращены поимённо. Если понадобится уважать системную
настройку — не резать движение, а не запускать сценарий автоматически и дать
кнопку воспроизведения. Логотип — статичный элемент без ссылки и отклика.
Плашки «5.0 Яндекс.Карты» и «Хорошее место 2026» временно сняты
(координаты — в комментарии в `Hero.tsx`).

## Что дальше

- **Мобильная версия** — макета нет, поэтому ниже 1024 работает автоматическая раскладка
  [`src/app/mobile.css`](./src/app/mobile.css): координаты `box()` превращаются в поток,
  секции встают в одну колонку. Ручные доработки — там же, по секции на блок.
  Проверка: `node scripts/mobile.mjs` (снимки в `docs/shots/mobile/`, список вылезающих
  за экран элементов). Десктоп файл не затрагивает — `verify.mjs` сходится 20/20.
  «Выбери зал» на телефоне — отдельный компонент `HallsMobile.tsx`: подзаголовок, табы
  площадок, лента домов по кругу (свайп; по краям — копии крайних домов, на которые лента
  после остановки незаметно переставляется). Постоянного блока под домом нет — названия и
  площади нарисованы на этажах. Нажатие по этажу подсвечивает его и всплывает карточка:
  название, площадь, адрес и «Выбрать зал»; в заказ зал кладёт только кнопка, повторное
  нажатие по этажу карточку сворачивает. Внизу «ВСЕ ЗАЛЫ» с веером фотографий, как на
  десктопе: веер разыгрывается один раз, когда кнопка входит в кадр, и уходит обратно.
  Картинки домов — `public/halls/mobile/*.webp`, собраны из PNG «… — моб.png» с обрезкой
  прозрачных полей; контуры этажей заданы в процентах исходной PNG и пересчитываются по
  полям обрезки (`crop` в компоненте). Стикеры шагов 1–4 и галочка — те же, что на
  десктопе, приклеены к первой букве заголовка: `StepDone.tsx` меряет её в браузере.
  Страница залов (`/halls`) ниже 1024 — отдельный блок в конце `src/app/halls.css`: первый
  экран с текстом внизу, одна колонка карточек (на планшете две), подвал 2×2. Кадры в
  карточке и в полноэкранном просмотре листаются свайпом (`src/lib/useSwipe.ts`), стрелки
  на сенсорных экранах видны всегда, у просмотра на телефоне есть крестик.
  Reels на сенсорных экранах (`hover: none`) работает как сторис: сам играет ролик в
  центре ленты, касание — пауза, доиграл — лента едет к следующему, внизу полоска
  прогресса; за экраном и в свёрнутой вкладке — пауза, при экономии трафика и
  reduced-motion — только по касанию. Грузится только играющий ролик; облегчённые
  версии для телефона не делаем — на тёмных кадрах с движением они рассыпались на квадраты.
  Ролики со звуком, по умолчанию он выключен; кнопка в правом верхнем углу включает звук
  сразу у всех Reels. Звук взят из исходников в папке «видео reels» (`*-01.mp4`) и
  подмешан в веб-версии без перекодирования картинки:

  ```bash
  ffmpeg -y -i public/video/reels/black-full.mp4 -i "видео reels/black-01.mp4" -map 0:v:0 -map 1:a:0 -c:v copy -c:a aac -b:a 96k -shortest -movflags +faststart black-full.tmp.mp4
  ```
