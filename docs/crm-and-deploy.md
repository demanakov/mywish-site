# Форма → amoCRM и выкладка на хостинг

Что осталось сделать, чтобы сайт заработал на боевом домене. Устройство
проекта — в `README.md` и `docs/handoff.md`.

## Запуск

Нужен Node.js 20.9+ (проект собирался на Node 24).

```bash
npm ci            # зависимости строго по package-lock.json
npm run dev       # разработка, http://localhost:3000
npm run check     # линтер, типы, юнит-тесты и боевая сборка
npm start         # запуск сборки на :3000
npm run test:e2e  # браузерная регрессия (сервер должен быть запущен)
```

Перед боевой сборкой задать домен: `NEXT_PUBLIC_SITE_URL=https://…`
(образец — `.env.example`). От него строятся canonical, `sitemap.xml`,
`robots.txt` и превью ссылок.

Все маршруты статические: `/`, `/halls`, `/menu`, документы `/privacy`,
`/consent`, `/cookies`, `/requisites`. Те же проверки GitHub запускает сам
на каждый push (`.github/workflows/check.yml`).

## 1. Форма заявки — сейчас НИКУДА не отправляет

`src/components/RequestForm.tsx`, функция `onSubmit`:

- после проверки полей вызывается `markSent()` — человек сразу видит «заявка
  отправлена», хотя запроса нет;
- объект `payload` собран и выброшен (`void payload`) — это и есть точка
  подключения.

Что нужно:

1. Отправлять `payload` на свой серверный обработчик (см. раздел 2), а не
   напрямую в amoCRM из браузера: ключ доступа amoCRM в клиентском коде
   увидит любой посетитель.
2. `markSent()` вызывать только после успешного ответа. На ошибку — показать
   сообщение и оставить введённые данные в форме, чтобы заявку можно было
   отправить повторно.
3. На время запроса блокировать повторную отправку (двойной клик = две сделки).

Состав `payload`:

| Поле | Что это |
| --- | --- |
| `hall` | выбранный зал |
| `date`, `pkg`, `hours` | дата (`YYYY-MM-DD`), пакет (id, например `"extra"`) и часы — **только если человек выбрал их сам**, иначе `null` |
| `dateTouched`, `pkgTouched`, `hoursTouched` | выбирал ли человек это сам |
| `estimate.pkg`, `estimate.hours`, `estimate.total` | что показано в расчёте, включая значения по умолчанию; `total` — `null`, пока нет даты |
| `name`, `phone` | имя и нормализованный телефон |
| `guests`, `messenger`, `wish` | гости, нормализованный контакт в мессенджере, пожелания |
| `consent.version`, `consent.acceptedAt` | редакция согласия на обработку ПДн и время отметки галочки |

`consent` обязательно сохранить вместе с заявкой (поле сделки или примечание):
текст согласия прямо обещает, что версия и время отметки фиксируются, — по ним
потом доказывают, на какую редакцию человек соглашался.

Ключи amoCRM — только в переменных окружения на сервере (`.env`, он в
`.gitignore`), не в репозитории.

## 2. Хостинг (Beget)

Текущий сайт уже живёт на Beget. Перед заменой — сделать резервную копию
старого сайта.

Выбор зависит от тарифа:

**Вариант А — Node.js (VPS или тариф с поддержкой Node).**
Обработчик формы делается прямо в проекте: `src/app/api/lead/route.ts`
(Route Handler, принимает `POST` с `payload`, отправляет в amoCRM). На сервере:
`npm ci && npm run build && npm start` под pm2/systemd, перед ним nginx
с доменом и HTTPS.

**Вариант Б — обычный виртуальный хостинг (PHP, без Node).**
Сайт полностью статический, его можно выгрузить готовыми файлами:

- в `next.config.ts` добавить `output: "export"`, `trailingSlash: true`
  (чтобы `/halls` лёг как `halls/index.html` и открывался на Apache) и
  `images: { unoptimized: true }` (`next/image` используется в
  `FoodMenuModal.tsx`, оптимизатор без Node не работает);
- удалить служебный маршрут `src/app/api/dev/anchors/` (статическая выгрузка
  не собирается с серверными обработчиками). Это инструмент разработки:
  панель `AnchorTuner` (открывается с `?anchors` в адресе) через него пишет
  отступы разделов в `src/app/anchors.css`; на собранном сайте он и так
  отвечает 404. Саму панель можно оставить или убрать из `src/app/page.tsx`;
- `npm run build` → содержимое папки `out/` залить в корень сайта;
- обработчик формы — небольшой PHP-скрипт на том же домене, который
  принимает `payload` и отправляет в amoCRM.

Важно: Next.js в этом проекте — версия 16, API и настройки отличаются от
старых версий. Документация лежит в `node_modules/next/dist/docs/` — сверяться
с ней, а не с памятью.

## 3. Перед запуском на домене

- Мобильная версия есть (ниже 1024px): форму и отправку проверять и
  на телефоне.
- В тексте политики конфиденциальности (`src/lib/legal.ts`) указан домен
  mwsh.ru — заменить на боевой, если он другой.
- Персональные данные граждан РФ по 152-ФЗ должны первично собираться на
  серверах в России — Beget этому соответствует.
- Проверить отправку формы на боевом домене: заявка появилась в amoCRM,
  согласие сохранилось, при ошибке сети человек видит сообщение.
