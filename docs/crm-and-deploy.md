## Как устроена отправка

Все точки входа новой главной и каталога залов ведут в общий `src/components/RequestForm.tsx`.
Компонент отправляет JSON на `/api/leads.php`. PHP сохраняет заявку в существующую SQLite,
затем передаёт её в amoCRM и Telegram. Ключи находятся только в закрытой конфигурации Beget.

Адаптер `src/lib/lead-payload.mjs` сохраняет имя, телефон, мессенджер, пожелание,
выбранный зал, дату, пакет, длительность, диапазон гостей, расчёт, согласие и атрибуцию.
Пакет и дата по умолчанию не выдаются за выбор клиента. Диапазон «до 15» остаётся
диапазоном в примечании; он не превращается в точное количество гостей.
`base_estimate` передаётся только при явном выборе даты, пакета и часов.

Обязательный контракт:

- `POST /api/leads.php`, `Content-Type: application/json`, тот же домен;
- `form_id: main_dmitry_request`;
- `consent: true`, `consented_at` – момент отметки, `consent_version` и `policy_version`;
- UTM, `yclid`, `ym_client_id`, `matched_keyword`, `region_id`, `landing_path`;
- `request_id` – один идентификатор на повторные попытки до подтверждения сохранения;
- успех – HTTP 201/202, `accepted: true` и положительный `leadNumber`;
- HTTP 202 с номером означает сохранённую заявку: доставка может ещё ожидать повтора;
- на ошибку форма сохраняет данные; повторный клик во время запроса заблокирован.

`form_success` счётчика Метрики `111392359` вызывается только после подтверждения записи.
Содержимое полей закрыто от Вебвизора. Имена, контакты и текст заявки не передаются в цели.
Старые `home_request`, `hero_callback`, `rental_callback` и `prazdnik_request` поддерживаются.

## Что сохранять при следующих правках

Дмитрий продолжает работу из этого интегрированного проекта. Нельзя заменять его старой
выгрузкой из GitHub или возвращать локальный `markSent()` без запроса к API.
Дизайн, тексты, фото, меню и цены можно менять в обычных компонентах и источниках данных.
При изменении формы нужно сохранять адаптер, согласие, обработку ошибок и идентификатор запроса.

GitHub хранит исходный код. SSH доставляет на Beget готовую папку `out/` после сборки.
Сам по себе push в GitHub сайт не обновляет: автоматическая публикация не настроена.
Интеграция сохраняется, если следующая сборка сделана из этого проекта, а серверный
обработчик и закрытая конфигурация остаются на месте.

## Локальная работа

Выпуск проверен на Node.js 26.0.0 и npm 11.12.1; для браузерных проверок нужен Google Chrome.

```bash
npm ci
npm run dev
npm run check
npm start
```

`npm run build` создаёт статическую папку `out/`. `npm start` показывает её на
`http://127.0.0.1:3000`; PHP API работает на Beget, а не в локальном предпросмотре.
`NEXT_PUBLIC_SITE_URL` по умолчанию равен `https://mwsh.ru`.

Целевая браузерная проверка с подменённым ответом API не создаёт сделки и уведомления:

```bash
BASE_URL=http://127.0.0.1:3000 npm run test:integration
BASE_URL=http://127.0.0.1:3000 npm run test:calculator
```

Перед сборкой не нужна повторная установка amoCRM или Telegram.
Служебная запись отступов `AnchorTuner` исключена из production. Исходник её POST-обработчика
сохранён в `tools/development/anchors-route.ts`; обычные отступы меняются в `src/app/anchors.css`.

## Публикация на Beget

Корень проекта на сервере: `/home/m/mywishd7/mywish`.
Публичная часть – `public_html`, закрытая – `private`.
Доступ Дмитрий получает отдельно у владельца; ключей и паролей в архиве нет.

1. Сохранить изменения в Git и выполнить `npm run check`, затем браузерные проверки.
2. Сделать серверную резервную копию изменяемых файлов и SQLite через штатный backup API
   или `sqlite3 .backup`. Копирование активной SQLite обычным `cp` не подходит.
3. Загрузить `out/` сначала в новый каталог `releases/`. Сравнить список и контрольные суммы.
4. Добавить новые ресурсы и заменить одноимённые файлы атомарно; `index.html` заменить последним.
   Не использовать `--delete` для всего `public_html` и не заменять его целиком.
5. Проверить главную, каталог, меню, документы, формы, калькулятор, мобильную версию и цели.
   Факт доставки в amoCRM/Telegram подтверждать серверными статусами, а не только экраном успеха.

Для первой установки этого выпуска нужен обновлённый
`deployment/beget/public_html/api/leads.php`. В нём добавлены новая форма и таблица
`lead_form_requests`, которая защищает запись от повторов, включая одновременные запросы.
Синтаксис совместим с PHP 5.6. При следующих изменениях только дизайна этот файл
загружать повторно не требуется. Рабочие `api/_bootstrap.php`, `private/bootstrap.php`,
`private/config.php`, базы, токены, webhook и настройки amoCRM сохраняются.

Существующие `/prazdnik/`, `/thanks/`, `/about/`, статьи, страницы отдельных залов,
конструкторы, API, проверочные файлы поисковых систем и `.htaccess` сохраняются.
Их адреса сохранены в sitemap; ограничения robots для служебных разделов также сохранены.
У 26 сохранённых страниц прежнего приложения добавлены обычные переходы между
страницами, чтобы их клиентский роутер не пытался загрузить новую главную как старое приложение.

## Прежняя версия и откат

Прежний сайт доступен на `https://mwsh.ru/previous/`. У него отдельные HTML, скрипты и стили,
переходы между своими страницами и своя страница благодарности; API остаётся общим.
Исходные `/media/`, `/fonts/` и `/ruby-lab/` сохраняются на сервере: архив использует
их прежние адреса. Не удалять их при очистке ресурсов новой версии.
Раздел получает `X-Robots-Tag: noindex, follow`. Его цены – историческая версия.

Резервная копия перед заменой: `/home/m/mywishd7/mywish/backups/main-dmitry-20260916-1947/`.
`production-files.tar.gz` содержит прежние файлы, а `leads.sqlite3` и `data.sqlite` –
отдельные консистентные снимки. Этот каталог закрытый и не входит в передаваемый архив.

Для отката интерфейса восстановить прежние HTML и ресурсы из резервной копии.
Рабочую базу после запуска не откатывать вместе с файлами: в ней могут быть новые заявки.
Обновлённый API совместим со старым интерфейсом и может оставаться на сервере при откате.
