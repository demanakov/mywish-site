Автор: demanakov. Выпуск от 16 сентября 2026 года.

Сайт опубликован на [mwsh.ru](https://mwsh.ru/). Предыдущая версия – [previous](https://mwsh.ru/previous/).
В архиве находится полный проект с подключённой формой, статической сборкой для Beget
и исходником совместимого PHP-обработчика. Секретов, базы заявок и SSH-ключей в нём нет.

## Как продолжать работу

1. Распакуй `MyWish_исходники_2026-09-16.zip` и используй папку `mywish-site/` как рабочий проект.
   Не возвращай поверх неё старый компонент формы из прежней версии.
2. Установи зависимости командой `npm ci`, запусти `npm run dev` и внеси правки.
3. Выполни `npm run check`. После сборки `npm start` откроет итоговый сайт на порту 3000.
   Локальный предпросмотр не запускает PHP; API работает на хостинге.
4. Запусти `npm run test:integration` и `npm run test:calculator`, указав
   `BASE_URL=http://127.0.0.1:3000`. Проверки подменяют отправку и не создают реальные заявки.
5. Сохрани изменения в отдельной ветке GitHub и передай Денису pull request,
   коммит и список правок. Проверку и публикацию на Beget выполняем после решения Дениса.

Выпуск проверен на Node.js 26.0.0, npm 11.12.1 и Google Chrome.
Не использовать очистку всего `public_html` или загрузку с `--delete`.
Не заменять `private`, базы, серверные ключи, `.htaccess`, API и сохранённые старые страницы.
Файл `deployment/beget/public_html/api/leads.php` уже установлен на сервере.
При изменениях только дизайна повторная настройка amoCRM и Telegram не нужна.

Если удобнее сохранить историю текущего Git-репозитория, приложен `Интеграция.patch`.
Он рассчитан на исходную версию `d1f27565e5413a254c0cd266d19c72907846165d`:

```bash
git switch -c integrate-main-20260916 d1f27565e5413a254c0cd266d19c72907846165d
git am /путь/к/Интеграция.patch
```

Перед этим сохрани собственные незакоммиченные изменения. Патч переносит в том числе
удаление dev-маршрута `src/app/api/dev/anchors/route.ts`, несовместимого со статическим экспортом.
Его исходник оставлен в `tools/development/anchors-route.ts`.

GitHub – место хранения исходников и истории. SSH – способ доставки готовых файлов на сервер.
Один push в GitHub сайт не обновляет. Интеграция останется рабочей, если сборка сделана
из переданного проекта, контракт формы сохранён, а действующий backend оставлен на сервере.
